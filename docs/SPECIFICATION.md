# Спецификация функциональности Сопут

Продукт: сервис подбора **сопутствующих товаров** к карточкам каталога [komus.ru](https://www.komus.ru/). Цель — добор чека расходниками и комплектом «с этим покупают», а не показ аналогов с той же полки.

Аудитории:

1. **Покупатель / виджет витрины** — блоки сопутки на карточке и в корзине.
2. **Мерчандайзер** — верстак закрепления и скрытия, правила категорий, покрытие.
3. **Интегратор** — HTTP API.
4. **Другой агент / пайплайн** — gzip-дамп каталога без скрейпа Комус.

Живой контур: `http://84.201.169.67/`. Репозиторий: [github.com/iltarus/SOPUT](https://github.com/iltarus/SOPUT).

---

## 1. Цель и границы

### 1.1. Делает

- Хранит полный снимок товарных URL Комус (~170 тыс. SKU) плюс размеченный демо-срез.
- К любому известному артикулу возвращает ранжированный список сопутствующих (до 24, на PDP обычно 8–12).
- Группирует выдачу: закреплено / расходники / подходит к технике / с этим покупают.
- Даёт поиск и пагинацию по каталогу, карточку товара, корзину, верстак, правила, отчёт покрытия.
- Отдаёт тот же движок по HTTP для виджета на komus.ru.

### 1.2. Не делает

- Не продаёт и не оформляет заказ.
- Не подтягивает актуальные цены и остатки Комус (sitemap их не содержит).
- Не является поиском «похожих» товаров: второй степлер при степлере — ошибка, не фича.
- Не парсит HTML карточек Комус в рантайме (антибот).

### 1.3. Определение «сопутствующий»

Сопутствующий товар закрывает использование исходного: расходник, аксессуар, норма комплекта, совместная закупка. Подмена той же категории без compat/affinity понижается в ранге и обычно не попадает в топ.

## 2. Каталог

### 2.1. Идентификатор

- Основной ключ — артикул Комус = `id` = `sku` для sitemap-строк.
- Живая карточка: `https://www.komus.ru/p/{id}/`, если товар пришёл из sitemap (`path` заполнен).
- Демо-id без sitemap: ссылка «Карточка на komus.ru» открывает поиск по бренду и названию, **не** `/p/{demoId}/` (такие URL на Комус 404).

### 2.2. Состав карточки

| Поле | Sitemap | Featured |
|---|---|---|
| Название | обратная транслитерация slug | витринное |
| Бренд | эвристика токена или «Комус» | задан |
| Отдел `department` | 22 значения, см. `src/lib/departments.ts` | задан |
| Категория | из slug | задана |
| Картинка | CDN `media.komus.ru` или пусто | задана |
| Цена / остаток | нет (0 / «на komus.ru») | заданы |
| Атрибуты, теги, описание | пусто | заданы |

### 2.3. Поиск

- Запрос `q`: подстрока без морфологии по id, имени, бренду, категории, пути.
- Точное совпадение id поднимается первым.
- Фильтры: отдел, категория.
- Пагинация: `offset`, `limit` (UI 48, API максимум 96).
- Пустой результат — штатное состояние, не ошибка.

### 2.4. Отделы

`stationery`, `paper`, `print`, `computers`, `electronics`, `appliances`, `furniture`, `cleaning`, `packaging`, `workwear`, `food`, `kitchen`, `tools`, `school`, `home`, `beauty`, `sport`, `gifts`, `seasonal`, `safety`, `trade`, `other`.

## 3. Рекомендации к карточке (PDP)

### 3.1. Вход

- Обязательно: `productId`, существующий в каталоге.
- Опционально: `limit` (1–24, по умолчанию 12 в related API, 8 на `GET /api/products/{id}`), `context=pdp|cart`.

### 3.2. Выход

JSON:

- `productId`, `context`
- `coverage`: `{ score, label }` — «Полное покрытие» / «Достаточное покрытие» / «Слабое покрытие» / «Нет рекомендаций»
- `groups[]`: непустые группы с `id`, `title`, `items[]`
- `items[]`: плоский список в порядке ранжирования

Элемент рекомендации: сериализованный товар + `score`, `group`, `reasons[]` (`type`, `label`, `weight`), ссылки `url`, `workbenchUrl`, `komusUrl`.

### 3.3. Правила ранжирования (продуктовые)

| Приоритет | Сигнал | Пример |
|---|---|---|
| 1 | Закрепление мерчандайзера | пин в верстаке всегда первый |
| 2 | Совместимость SKU | HP 107a → картридж 107A |
| 3 | Правило категорий + ключевые слова | степлер → скобы; стол → кресло |
| 4 | Совместные покупки (синтетические заказы) | принтер + бумага A4 |
| 5 | Тот же бренд (не «Комус») на другой полке | |
| 6 | Комплект отдела, если точных расходников нет | мебель → канцелярия/хозтовары |
| 7 | Наличие (для featured) | нет в наличии — вниз |

Скрытый в верстаке SKU в выдачу не попадает. Услуги «заправка картриджа», «восстановление», «ремонт» в сопутку не предлагаются.

### 3.4. Покрытие на живой карточке

- 0 позиций → «Нет рекомендаций»
- есть позиции, но нет одновременно расходников и together / мало слотов → «Слабое»
- ≥3 и есть расходники **или** together → «Достаточное»
- ≥6 и есть расходники **и** together → «Полное»

Это **не** тот же KPI, что на `/coverage` (там порог — число сопутствующих в офлайн-снимке).

### 3.5. Приёмочные примеры

| Источник | Обязано быть | Не должно быть |
|---|---|---|
| Featured `148201` HP LaserJet 107a | `148202`, `148203`, бумага A4 | тонер Brother `148221`/`148222` |
| Степлер №10 `120201` | скобы №10 `120202` | скобы 23/13 выше №10 |
| Живой степлер `1271903` | позиции со «скоб» в названии | пустая выдача |
| Живой принтер `1042218` | бумага и/или картриджи | «Заправка картриджа … город» |
| Стол `2372300` | кресло / коврик под кресло / лоток | пустая выдача |
| Шуруповёрт `1747684` | биты, саморезы или СИЗ | продукты питания |

## 4. Корзина

### 4.1. Клиент

- Добавить / убрать / изменить qty / очистить.
- Хранение только в браузере (`localStorage`).
- Счётчик в шапке.

### 4.2. Сопутка к корзине

`POST /api/cart/related` тело `{ ids: string[], limit?: number }`.

- Пустой `ids` → `{ items: [], message: "Корзина пуста" }`, не 4xx.
- Уже лежащие в корзине id в выдачу не попадают.
- Одна позиция может набирать score от нескольких якорей корзины.

---

## 5. Верстак мерчандайзера

Маршруты `/workbench`, `/workbench/[id]`.

### 5.1. Поиск якоря

Поиск по каталогу, выбор артикула, переход на редактор выдачи.

### 5.2. Действия на связанной позиции

| action | Эффект |
|---|---|
| `pin` | id в начало списка пинов, снимается hide |
| `unpin` | убрать из пинов |
| `hide` | исключить из выдачи, снять пин |
| `unhide` | вернуть в автоматическую выдачу |

Пишется в `data/overrides.json` (`pins`, `hidden`). Без истории версий и без ролевой модели: кто достучался до API, тот меняет файл.

### 5.3. API

```
GET  /api/overrides
POST /api/overrides
{ "productId": "148201", "relatedId": "120300", "action": "pin" }
```

400, если нет `productId`, `relatedId` или `action`.

## 6. Правила категорий

Страница `/rules` и `GET /api/rules`.

Справочник `src/lib/rules.ts`: `fromCategory` → `toCategory`, вес, kind (`consumable` | `accessory` | `workflow`), человекочитаемая причина. Сопоставление с живыми категориями sitemap — по вхождению строки, не только exact match featured-названий.

Редактирование правил в UI **не** предусмотрено (только просмотр). Изменение — правкой кода и деплоем.

## 7. Покрытие витрины

Страница `/coverage`. KPI на главной: «Покрытие витрины».

### 7.1. Снимок

Офлайн `npm run coverage:build` по **всем** id каталога. Для каждого: до 8 сопутствующих, метка:

| Сопутствующих | Метка снимка |
|---|---|
| ≥ 6 | Полное |
| 3–5 | Достаточное |
| 1–2 | Слабое |
| 0 | Нет рекомендаций |

`coveragePct = round(100 × (full + ok) / total)`.

### 7.2. UI / API

- Фильтры: текст, отдел, метка.
- Пагинация по 50.
- `GET /api/coverage?q=&department=&label=&offset=&limit=`
- `GET /api/coverage?id={артикул}` — одна строка снимка; 404 если id нет в снимке.

Слабые и пустые в дефолтной сортировке снимка идут раньше (меньше count/score). После полного прогона с запасным пулом отделов пустых может не быть: KPI 100% означает «у каждой карточки ≥6 позиций в снимке», а не идеальное качество OEM.

## 8. Витрина

### 8.1. Главная `/`

- KPI: число товаров, покрытие %, число правил, объём синтетических заказов.
- Примеры товаров и отделов.
- Каталог с поиском, фильтром отдела, подгрузкой страниц через `/api/products`.
- Блок «верстак» на геро не показывается (верстак — отдельный пункт меню).

### 8.2. Карточка `/p/{id}`

- Фото (или заглушка отдела), артикул, бренд, цена, ссылка на Комус, «в верстак», «в корзину».
- Рейлы сопутки по группам.
- Неизвестный id → 404.

### 8.3. Адаптив

Шапка: меню-sheet на мобиле, горизонтальная навигация на desktop. Карточки и сетка каталога сжимаются.

## 9. HTTP API (контракт интегратора)

База: тот же хост, что витрина. JSON UTF-8.

### 9.1. `GET /api/products`

Query: `q`, `department`, `category`, `offset`, `limit`.

Ответ: `{ total, offset, items: SerializedProduct[] }`.

### 9.2. `GET /api/products/{id}`

200: `{ product, related }`  
404: `{ error: "Товар не найден" }`

### 9.3. `GET /api/products/{id}/related`

Query: `limit`, `context=pdp|cart`.  
404 если товара нет.

### 9.4. `POST /api/cart/related`

Тело `{ ids, limit? }`. Ответ `{ items, count }`.

### 9.5. Прочее

- `GET /api/rules` → `{ total, items }`
- `GET /api/catalog` → локатор дампа
- `GET /api/catalog/dump` → `application/gzip` вложение `komus-catalog.json.gz`
- Документация для людей: `/docs`

Идемпотентность: GET без побочных эффектов. POST overrides меняет файл на диске процесса.

## 10. Передача каталога другому исполнителю

Не скрейпить komus.ru. Не искать XML в `/tmp`.

1. Файл `data/komus-catalog.json.gz` + контракт `data/HANDOFF.md` / `data/README.md`.
2. CLI: `python3 scripts/query-komus-catalog.py --stats|--id|--q|--department`.
3. HTTP: `http://84.201.169.67/dumps/komus-catalog.json.gz` и `/dumps/catalog-locator.json`.

Поиск по репозиторию часто **не видит** `*.gz` — начинать с `data/komus-catalog.meta.json`.

## 11. Нефункциональные требования

| Тема | Требование |
|---|---|
| Память VM | Процесс должен жить в ≤1500 MB RSS; каталог packed; покрытие — ndjson, не полный JSON.parse |
| Старт | `npm run build && npm start`; каталог читается при импорте `catalog.ts` |
| Тесты | `npm test` — регрессия принтера, степлера, пинов, корзины, sitemap-id, чужого тонера, стола, шуруповёрта, заправок |
| Язык UI | Русский |
| Ошибки API | 400 валидация overrides; 404 неизвестный товар/снимок; пустая корзина — 200 |
| Наблюдаемость | KPI покрытия и страница `/coverage`; отдельного APM нет |

## 12. Вне скоупа текущей версии

- HTTPS и домен
- Авторизация мерчандайзера
- Редактор правил в UI
- Живой прайс/остаток Комус
- Персонализация по пользователю
- Модель кликов/заказов с настоящей витрины (сейчас синтетические корзины featured-среза)
